## 一、任务定义

**目标**:给定一张输入图片,把它转换成由"三角砖"拼成的近似图像(类似马赛克/像素化效果)。

**砖块定义**(写代码前要确定清楚):

- 二维**直角等腰三角形**
- 砖块大小 = 两条相等直角边的长度(以基础网格为单位,例:1 / 2 / 4 / 8)
- 每个三角形 = 一块砖,一个**统一面色**,由它所覆盖的图像区域决定
- 砖块必须**无间隙、无重叠**地铺满输出图像
- 边界线可以画出来,不计作额外颜色

## 七、贯穿作业的核心问题(作业设计哲学)

> 这一节是整个作业的**总纲**,回答:「给定图像,在≤10000 块三角预算下,如何让输出最像原图?」

### 7.1 核心 trade-off(三维度,不是单维度)

直觉上三角越多 → 细节越丰富 → 特征保留越好。但这是一个**多维度问题**,因为:

| 维度 | 含义 | 与密度的关系 |
|------|------|-------------|
| **细节保留**(信号) | 边缘、纹理、轮廓 | 密度↑ 时保留↑ |
| **噪声放大**(噪声) | 传感器噪点、JPEG 瑕疵 | 密度↑ 时**也↑**——单三角覆盖像素少时,均值估计的方差 ≈ σ²/N,N 小则方差大,把噪声当细节 |
| **量化损失** | 颜色离散化丢的颜色微差 | 与密度**独立**,只取决于调色板大小和阈值算法 |

所以核心问题不是"三角越多越好",而是**信息密度的均匀分配**:
- 哪儿局部方差大(信号主导)→ 小三角保留细节
- 哪儿局部方差小(平坦区域)→ 大三角不丢信息、节约预算
- 哪儿局部方差小但是噪声主导(例如低光 JPEG 块)→ 用大三角**主动平滑**,避免假细节

### 7.2 形式化(给报告"问题描述"那一段用)

> **优化目标**:在 2·M·N ≤ 10000 的预算下,选定三角大小、划分方式与颜色量化,使输出图与原图的感知相似度(SSIM / PSNR / 视觉)最大化。
>
> **决策变量**:
> - **密度**:每个三角的直角边长 S(Task 2 固定为常数;Task 3 自适应)
> - **划分**:在哪些位置用大三角、哪些位置用小三角(Task 2 无;Task 3 自适应)
> - **颜色**:调色板大小 K 与量化方式(Task 2: K=3 Multi-Otsu;Task 3: K>3,K-Means / Median Cut)
> - **边界**:不整除像素的处理(默认丢弃最后一行/列)
>
> **约束**:无缝、无重叠、三角形总数 ≤ 10000、调色板大小固定。

### 7.3 各 Task 如何回应这个核心问题

| Task | 决策自由度 | 回应方式 |
|------|------------|---------|
| 2 | 全部固定 | 「在均匀网格 + 棋盘对角线 + Otsu 标量量化的约束下,临界 S 给出信息保留最多的固定解」 |
| 3 | 密度 + 划分自适应 | 「Quad-tree 递归剖分,按局部方差阈值决定是否细分」——**真正解决问题** |
| 4 | 同 Task 3 + 时间维度 | 「实时约束下,加上帧间稳定性(调色板 EMA 平滑)+ 性能(降分辨率 / 缓存 mask)」 |
| 5 | — | 把上述 trade-off 的实验对比(不同 S、不同 K、不同量化方法、不同划分策略)写进报告 |

## 八、建议工作流

1. **Task 2**:先用 PolyU GenAI 出基础版(等大三角 + 3 色),自己跑通,确认每块颜色取自所覆盖区域(常用做法:取区域均值 → 最近邻到 {白/灰/黑})。
2. **Task 3**:在 Task 2 基础上加多尺寸。最朴素的做法:**基于图像方差/边缘密度**把小区域合并成大三角;颜色量化从 3 色 → N 色(可走 k-means 或简单桶)。
3. **Task 4**:接摄像头(`cv2.VideoCapture`),把 Task 3 的函数做成帧处理。**这里必须改 AI 代码**:加实时性、异常处理、不同分辨率/光照下的稳定性。
4. **Task 5**:边写代码边记素材(截图、对比图),最后填模板;**单独留一节写 AI 局限性**(比如:AI 没考虑光照、AI 的颜色量化在边界处会有锯齿等)。
